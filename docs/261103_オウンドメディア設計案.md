# えんまーる オウンドメディア 設計案（v0.1）

- 作成日: 2026/11/03
- 目的: えんまーるの潜在保育士の集客。ゴールは **公式LINE の友だち追加** または **メールアドレスの獲得**
- 前提資料: 株式会社eggside 太田様「SEOメディアの初期設計案」（2026/10/31）の第1部・第3部・第4部（LA-Eye／LA-Edge の箇所は対象外）
- 参照したリポジトリ（参照のみ・変更なし）: `document-hub-kasumin`（`master/サービス情報.md`・`master/会社情報.md`・`master/お問い合わせ先.md`）、`enmaru`（公開ページの構成）
- 公開範囲: 社内（設計資料）

---

## 1. 結論（先に要点）

1. **構成は「kasumin-hp リポジトリに2つ目の静的サイト `media/` を追加し、サブドメインで配信」** が良い。HP（`site/`）と同じ技術（Next.js 静的出力 + Markdown）・同じさくらVPS・同じ GitHub Actions で運用でき、追加コストがほぼない。
2. **`/jobs`（求人一覧）はメディア側ではなく、えんまーる本体（enmaru.kasumin.biz）に作るべき。** 求人データの正本はえんまーる本体にあり、静的サイトに写すと古い求人が残る（Google の求人構造化データのガイドライン違反になりやすい）。メディアは「長崎市の短時間求人の読み方」のような**解説記事**で求人系キーワードを取り、えんまーるの公開ページ（既存の `/nurseries`）へ送る役割にする。
3. 計測は **Search Console をドメインプロパティ（kasumin.biz）で1つ** 取ればサブドメインすべてを1回で計測できる。GA4/GTM は既存のコンテナ（`GTM-KKJ2KRB3`）を流用できる。**LINE 友だち追加そのものは GA4 では取れない**ため、「GA4 で LINE ボタンのクリック」＋「LINE 公式アカウントの流入経路分析で実際の友だち追加」の2段で見る。
4. 設計案の内容には、**目的に対して直したほうがよい点が7つ**ある（2章）。特に「他社名（タイミー等）を出す比較記事」「代表の経歴の表記（元園長10年）」「全国キーワードと長崎中心のサービスのずれ」は公開前に決める必要がある。

## 2. 目的に対して不適切・改善したほうがよい点（重要）

| # | 箇所（設計案） | 問題 | 提案 |
|---|---|---|---|
| 1 | 最初の15本 #1・#2（タイミー・単発アプリ6つの比較）、柱1「『タイミーは怖い？』への答え」 | 社内ルール（`document-hub-kasumin/master/サービス情報.md` 2-1）で「**他社名を出す比較は一般公開の資料では使わない**」と決めている。サジェストの「事件」「やばい」に乗る記事は、競合の評判を下げる内容と受け取られるリスクもある | 他社名を出すかは代表・担当（原崎）が判断する。出す場合は ①公式情報（規約・ヘルプ）だけを出典に事実を並べる ②評価語（危ない・やばい）を使わない ③公開前に記載内容を見直す日付を入れる。出さない場合は「単発アプリを選ぶときに確かめる5項目（資格確認・雇用形態・配置基準…）」のように**一般化**しても同じ検索意図に応えられる |

| 4 | 「PV獲得記事：サジェストワードを中心に平田さんの監修記事を量産」 | Google は「大量生成コンテンツの不正使用（scaled content abuse）」を明示的にスパム扱いしている。AI で量産し監修だけ付ける記事は、YMYL（お金・制度・雇用）領域で特に評価されにくい | 「量産」ではなく **月4〜6本＋既存記事の更新**（設計案の公開ペースのとおり）。一人称の記事（#9〜#11・#14）は代表の実体験を取材して書き、AI は構成と下書きの補助に限る。税・社会保険（#12）、日雇い派遣（#3）は社労士・税理士の確認を入れ、記事に確認者を明記する |

| 6 | ゴール「LINE 登録またはメアド獲得」 | メールアドレスを集めても、送る内容（メルマガ・ステップメール）と配信の仕組みが今はない。LINE はステップ配信（特典「ブランク保育士の復帰準備ガイド」）が既にある | **主 CTA は LINE に一本化**し、メールは「PDF をメールで受け取る」（既存の復帰準備ガイドを特典にする）程度に留める。メールを取る場合は、配信同意（特定電子メール法）とプライバシーポリシーへの同意をフォームに入れる。保存先は HP と同じ GAS → スプレッドシート（`scripts/gas/form-receiver.gs`）を流用できる |
| 7 | 制度記事（就職準備金・扶養・相談会カレンダー） | 金額・日程は年度で変わる。設計案の本文でも長崎の就職準備金が「20万円」、他県が「40万円」と書かれており、古い情報のまま残ると信頼を一気に失う | 記事のメタデータに `updatedAt`（最終更新日）と `reviewBy`（次回点検日）を持たせ、点検日を過ぎた記事を一覧で出すスクリプトを用意する（3-3）。数字は一次資料（県・市のページ）を出典として記事内にリンクする |

### そのほか小さな点

- **サブドメインはドメインの評価を引き継ぎにくい。** SEO だけなら `kasumin.biz/media/` のようなサブディレクトリのほうが立ち上がりは早い。ただし HP と運用を分けたい・ブランドを分けたいならサブドメインで問題ない（今回の判断どおりで可）。その代わり、**HP からの導線は「一旦不要」でも、HP フッターに1本だけリンクを置く**と、クロールが早くなり評価も少し渡せる。コストはほぼゼロなので公開時に入れることを勧める。
- **「潜在保育士」は本人が検索しない語**（設計案の指摘どおり）。メディア名・見出しでは「ブランクのある保育士」「保育士に戻りたい方」など読者の言葉を使い、「潜在保育士」は制度記事の中で定義して使う。
- **一般公開の記事に園名・体験談を出す場合**は公開の許可を取り、特定の園・個人が分からない書き方にする（document-hub-kasumin の CLAUDE.md のルール）。
- 公開時は **10本程度そろえてから** インデックスさせる（開発中・本数が少ない間は `noindex`）。中身の薄い状態でクロールされると、サブドメイン全体の評価が低く付く。

## 3. サイト構成とリポジトリ構成

### 3-1 ドメイン

| ホスト | 役割 | リポジトリ |
|---|---|---|
| `kasumin.biz` | 会社の HP（既存） | kasumin-hp `site/` |
| **`media.kasumin.biz`（名称は【要確認】）** | オウンドメディア（今回） | kasumin-hp **`media/`（新規）** |
| `enmaru.kasumin.biz` | えんまーる本体（登録・園一覧・将来の求人一覧） | enmaru |

サブドメイン名の候補: `media.kasumin.biz`（汎用）／`hoiku.kasumin.biz`（読者に内容が伝わる）。メディア名（例: 「えんまーるマガジン」など）を先に決め、それに合わせる。

### 3-2 URL 構成（メディア）

いただいた案をベースに、`/jobs` をえんまーる本体へ移し、柱（カテゴリ）と著者のページを足した。

```
media.kasumin.biz/
├─ /                         メディアトップ（新着・柱ごとの一覧・LINE CTA）
├─ /articles                 記事一覧（ページ送り）
│   └─ /articles/[slug]      記事（例: /articles/nagasaki-shushoku-junbikin）
├─ /category/[pillar]        柱ごとの一覧（spot / short-time / return / nagasaki / nursery）
│                            ※ 柱の記事（ピラー記事）は /articles/ 配下に置き、ここからリンク
├─ /authors/[slug]           著者・監修者のプロフィール（平田さん・確認者）※E-E-A-T 用
├─ /about                    メディアについて・運営会社・編集方針（出典・更新の方針）
├─ /service                  えんまーるの紹介（LINE CTA と enmaru.kasumin.biz への導線）
├─ /line（任意）             LINE 登録の LP（特典の説明。広告・Instagram からの着地にも使える）
├─ /privacy_policy           → kasumin.biz/privacy_policy へリンクでも可（メール取得をするなら必須）
├─ /sitemap.xml
└─ /robots.txt

enmaru.kasumin.biz/（えんまーる本体。enmaru リポジトリ側の検討事項）
├─ /nurseries, /nurseries/[id]   既存の公開ページ（園の一覧・詳細）
└─ /jobs, /jobs/[id]             将来: 公開の募集一覧（JobPosting 構造化データ）
```

- URL は**英数字の短い slug**（日付やカテゴリを URL に入れない。カテゴリを変えても URL が変わらないように）。
- `/service` は「えんまーるとは」を1ページで説明するページ。内容は `master/サービス情報.md` の HP 掲載文と「2-1 ハローワーク等との違い」をそのまま使う。

### 3-3 リポジトリ構成（kasumin-hp）

```
kasumin-hp/
├─ site/                     既存の HP（変更なし）
├─ media/                    ★新規: オウンドメディア（Next.js 静的出力）
│   ├─ app/
│   │   ├─ layout.tsx        GTM・Organization/WebSite の JSON-LD・共通 metadata
│   │   ├─ page.tsx          トップ
│   │   ├─ articles/page.tsx
│   │   ├─ articles/[slug]/page.tsx   Article・BreadcrumbList（＋FAQ）の JSON-LD
│   │   ├─ category/[pillar]/page.tsx
│   │   ├─ authors/[slug]/page.tsx    Person の JSON-LD
│   │   ├─ about/ service/ line/
│   │   ├─ sitemap.ts        記事の updatedAt を lastModified に入れる
│   │   └─ robots.ts         本番ホスト以外は Disallow（プレビューの重複インデックス防止）
│   ├─ components/
│   │   ├─ LineCta.tsx       CTA（読者の状態で文言を出し分け。経路別 lin.ee URL）
│   │   ├─ AuthorBox.tsx     著者・確認者・最終更新日
│   │   ├─ Summary.tsx       冒頭の要約
│   │   ├─ Faq.tsx           Q&A（表示と JSON-LD を同じデータから出す）
│   │   ├─ Sources.tsx       出典一覧
│   │   └─ JsonLd.tsx        構造化データ出力の共通部品
│   ├─ content/
│   │   ├─ articles/         記事の Markdown（1記事1ファイル）
│   │   ├─ authors/          著者プロフィール
│   │   └─ pillars.ts        柱の定義（名前・説明・並び順）
│   ├─ lib/
│   │   ├─ articles.ts       Markdown 読み込み・frontmatter の型チェック
│   │   └─ seo.ts            URL・JSON-LD の生成
│   ├─ scripts/
│   │   └─ check-articles.mjs   frontmatter の必須項目・禁止語（マッチング・斡旋・他社名等）・
│   │                           点検日切れを検査（npm run check。CI で実行）／
│   │                           npm run stale で reviewBy を過ぎた記事の一覧
│   ├─ public/images/
│   └─ package.json
├─ scripts/
│   └─ gas/                  既存（weekly-report.gs にメディアの数字を追加）
├─ infra/nginx/
│   ├─ kasumin.conf          既存
│   └─ media.conf            ★新規: media.kasumin.biz の server ブロック（HTTPS・キャッシュ）
├─ docs/
│   └─ media/                ★新規: 編集方針・記事テンプレート・文言点検リスト・KPI 定義
└─ .github/workflows/
    ├─ deploy.yml            既存（paths: site/** に絞る）
    └─ deploy-media.yml      ★新規（paths: media/** → /var/www/media/ へ rsync）
```

**HP と同じリポジトリに入れる理由**: 構成（Next.js 静的出力・Markdown・さくらVPS・rsync）が同じで、手順書（`docs/260921_さくらVPS移行手順.md` など）と GAS をそのまま流用できる。`site/` と `media/` は別アプリにし、**ビルド・デプロイは独立**させる（記事を足しても HP は再デプロイされない）。共通部品が増えてきたら `packages/ui` に切り出す（最初は不要）。

**別リポジトリにする条件**: 外部ライター・制作会社（eggside 様など）に記事の編集権限を渡す場合。HP のコードやフォームの GAS と権限を分けたいなら、メディアだけ別リポジトリにする。

### 3-4 記事の frontmatter（案）

```yaml
---
slug: "nagasaki-shushoku-junbikin"
title: "長崎県の保育士就職準備金｜対象・期限・提出先（2026年度）"
description: "（120字前後。検索結果に出る説明文）"
pillar: "nagasaki"                 # spot / short-time / return / nagasaki / nursery
isPillar: false                    # 柱の記事なら true
targetKeyword: "長崎 保育士 就職準備金"
author: "hirata-kasumi"
reviewer: ""                       # 社労士・税理士など確認者（制度・税の記事は必須）
publishedAt: 2026-12-01
updatedAt: 2026-12-01
reviewBy: 2027-04-01               # 次回点検日（年度更新の記事は4月）
cta: "line"                        # line / register / line-area（県外向け）
lineRoute: "article"               # LINE 流入経路の識別子
faq:
  - q: "就職準備金は返さなくていいのですか？"
    a: "…"
sources:
  - title: "長崎県 保育士就職準備金貸付事業"
    url: "https://..."
noindex: false
---
```

記事の型（全記事で揃える）: 要約 → 本文（表を1つ以上）→ Q&A → 出典 → 著者・確認者・最終更新日 → CTA。設計案第3部の「要約と Q&A と表のある構成」と同じ。

## 4. 計測（GA4・GTM・Search Console）

| 項目 | 推奨 | 理由・注意 |
|---|---|---|
| Search Console | **ドメインプロパティ `kasumin.biz`**（DNS の TXT レコードで確認）を1つ作る。加えてメディアだけの URL プレフィックスプロパティ（`https://media.kasumin.biz/`）も作ると記事だけの数字が見やすい | ドメインプロパティはサブドメインをまとめて計測できる。サイトマップは `media.kasumin.biz/sitemap.xml` を送信 |
| GTM | 既存のコンテナ `GTM-KKJ2KRB3` を流用。`site/app/layout.tsx` のホスト判定（`kasumin.biz` とそのサブドメインだけで読み込む）をそのまま使える | コンテナを分けると管理が増える。メディア固有のタグはホスト名のトリガーで分ける |
| GA4 | 既存プロパティ（KASUMIN HP）に載せ、ホスト名で分けて見る。メディアの数字を独立させたい場合は新しいプロパティ | 同じプロパティにすると `weekly-report.gs`・Looker Studio を流用できる。enmaru 本体の登録まで追う段階では、enmaru にも同じ GTM を入れてクロスドメイン設定をする（enmaru リポジトリ側の作業） |
| LINE の計測 | ①GA4: LINE ボタンのクリックをイベント `line_click`（パラメータ: 記事 slug・柱・CTA の位置）で取る ②LINE 公式アカウント: **流入経路分析**用の URL を「記事」「HP」「Instagram」の3本程度作り、メディアの CTA は「記事」の URL を使う | GA4 では友だち追加の完了は取れない（LINE 側の画面で完了するため）。設計案どおり経路は2〜3本に絞る（少ない経路は「その他」に丸められる） |
| メールの計測 | フォーム送信成功時に `generate_lead` イベント | 入力内容（メールアドレス）を GA4 に送らない |
| KPI | 設計案第4部どおり「表示回数 → クリック率 → CTA のあるページの PV → CTA クリック率 → LINE 追加数」。加えて **長崎県内の読者の比率** | 2章 #3 のとおり、えんまーるで働ける読者かどうかを見る |

## 5. 構造化データ（JSON-LD）を入れる箇所

| ページ | 型 | 主な項目 |
|---|---|---|
| 全ページ（layout） | `Organization`（合同会社KASUMIN）、`WebSite`（メディア） | name・url・logo・sameAs（Instagram・公式LINE・HP） |
| 記事 | `Article`（または `BlogPosting`） | headline・description・image・datePublished・**dateModified**・author（`Person` へのリンク）・publisher |
| 記事・柱の一覧 | `BreadcrumbList` | トップ › 柱 › 記事 |
| 記事の Q&A | `FAQPage` | 表示している Q&A と同じ内容だけ。※2023年以降、一般サイトでは検索結果に FAQ のリッチリザルトは出ないが、内容の構造化として AI 検索には有効。入れて害はない |
| 著者ページ | `Person`（`ProfilePage`） | name・jobTitle・description・image・sameAs・worksFor |
| 柱・記事一覧 | `CollectionPage`／`ItemList` | 任意 |
| 求人（将来、enmaru 本体） | `JobPosting` | title・datePosted・**validThrough**・employmentType・hiringOrganization・jobLocation・baseSalary。**掲載中の募集だけ**に付け、終了したら外す（メディア側には付けない） |

`HowTo` は Google がリッチリザルトを終了しているので使わない。

## 6. 進め方（案）

| 段階 | やること | 目安 |
|---|---|---|

## 8. メディア名・サブドメイン名の候補

選ぶときの考え方:

- 検索結果ではタイトルの後ろに「｜メディア名」が付く。**初めて見た人にも保育士向けだと分かる名前**のほうがクリックされやすい。
- サブドメイン名そのものは検索順位にほぼ影響しない。**メディア名と揃えて、口頭で伝えやすい短い英数字**にする。
- 柱5（園の側・えんさぽ）も載せるため、えんまーるだけに寄せすぎない名前でもよい。
- 「おかえり保育士」は東京都の復職ガイドブックの名前として使われているため候補から外した。決める前に、同じ名前のメディア・商標がないか確認する【要確認】。

| # | メディア名 | サブドメイン | 意味・向いている点 | 気になる点 |
|---|---|---|---|---|
| A | **えんまーるマガジン** | `media.kasumin.biz`／`mag.kasumin.biz` | サービス名がそのまま入り、記事から LINE・登録に進んだときに迷わない。名前が覚えられればサービスの認知にもなる | 「えんまーる」をまだ誰も知らないので、名前だけでは保育士向けと分からない → タグライン（例:「保育士に、もう一度。」）を添える |
| B | **保育バディ通信** | `buddy.kasumin.biz` | 決定済みの愛称「保育バディ」を広める場になる（チラシ・SNS と揃う） | 「バディ」が何か初見で伝わりにくい。初出で意味を添える運用が必要 |
| C | **まーるノート** | `maaru.kasumin.biz` | 「まーる」（沖縄の方言で助け合い）＝えんまーるの由来。やわらかく、えんさぽの記事も載せやすい | 名前から保育が分からない →「保育士のための〜」の副題が必須 |
| D | **ほいくの戻り道** | `hoiku.kasumin.biz` | 読者の状況（ブランクから戻る）をそのまま名前にした。検索結果で内容が一目で伝わる | えんまーるとのつながりは副題（by えんまーる）で補う |

**おすすめ: A「えんまーるマガジン」＋ `media.kasumin.biz`**。メディアの目的はえんまーるの LINE 登録なので、名前でサービスを覚えてもらうのが最も直接的。タイトルは「記事タイトル｜えんまーるマガジン」、トップの副題に「ブランクのある保育士さんのための〜」を入れて内容を補う。愛称を広めることを重視するなら B。
