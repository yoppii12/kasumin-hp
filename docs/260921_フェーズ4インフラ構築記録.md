## 手順書からの差分・補足

- **暫定nginx設定**: DNS切替前のため、`infra/nginx/kasumin.conf` の443ブロックを外し
  80番で直接配信する暫定版（default_server・IPアクセス可）を
  `/etc/nginx/sites-available/kasumin.conf` に配置している。
  DNS切替時に本設定（リポジトリ版）へ差し替えて certbot を実行する
- **sudo NOPASSWD化**: 自動運用のため ubuntu の sudo をパスワードなしに変更
  （`/etc/sudoers.d/90-ubuntu-nopasswd`。SSHは鍵認証のみのため実質リスクなし）
- ローカル `~/.ssh/config` に `kasumin-hp`（133.125.39.168 / ubuntu / id_ed25519_sakura）を登録済み
- 雛形コピー時に残っていた laplust 用 `site/public/_redirects`（旧laplust URLの301定義）を削除。
  KASUMINは現行と同一URL構成のためリダイレクト不要
- `site/public/_headers` から存在しない `/images/posters/` を除去（本番のキャッシュ制御はnginx側）

## 残タスク

1. **GitHub Secrets登録**（ローカルで実行）:
   ```bash
   gh secret set VPS_HOST --body "133.125.39.168"
   gh secret set VPS_USER --body "ubuntu"
   ssh kasumin-hp 'cat ~/.ssh/deploy_key' | gh secret set VPS_SSH_KEY
   ```
   登録後、Actionsタブから「Deploy to Sakura VPS」を手動実行（workflow_dispatch）して成功確認
2. deploy.yml は main ブランチ push がトリガーのため、運用開始までに開発ブランチを main へ整理
3. 本登録（支払い確定）→ お試し帯域制限の解除確認
4. DNS切替 → SSL取得（手順書「切替」章のとおり）
5. GTM/GA4スニペット・フォームGAS（フェーズ3からの持ち越し）
