作成日: 2026年9月21日

DNSゾーンはさくらのまま動かさず、**変更はAレコード1件のみ**。MX・TXT・enmaruのCNAMEは絶対に触らない。

## 構成

```
GitHub main へ push
  → GitHub Actions（.github/workflows/deploy.yml）が自動ビルド
  → rsync で VPS の /var/www/kasumin/ へ同期
  → nginx が https://kasumin.biz として配信（SSLはLet's Encrypt自動更新）
```

- nginx設定: `infra/nginx/kasumin.conf`（本体のみ。**現行と同一URL構成のためリダイレクトmapは不要**）
- www.kasumin.biz はDNSレコードが存在しないため対象外

### パケットフィルター（さくらのコントロールパネル側）

**「パケットフィルターを利用しない」に設定する**（LAplustと同方針）。

- 初期状態のフィルターは SSH（TCP 22）のみ許可のため、そのままではWeb（80/443）が塞がれサイトを公開できない
- フィルターを外す場合、防壁はサーバー内の ufw のみになる。下記セットアップ手順のとおり
  **必ず `sudo ufw allow OpenSSH` を先に実行してから `sudo ufw enable` すること**（順番を誤るとSSHで締め出される）
- もし将来フィルターを再度利用する場合は、SSH（TCP 22）に加えて **Web（TCP 80/443）の許可ルールが必須**

## セットアップ（VPS上で1回だけ・約20分）

接続例: `ssh ubuntu@133.125.39.168`（契約時にインストールした公開鍵に対応する秘密鍵を使用）

```bash
# 1) nginxとcertbotのインストール
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx rsync

# 2) 配信ディレクトリ（デプロイユーザーが書き込めるように）
sudo mkdir -p /var/www/kasumin /var/www/certbot
sudo chown -R $USER:$USER /var/www/kasumin

# 3) リポジトリのnginx設定を配置
#    （ローカルPCから）
scp infra/nginx/kasumin.conf ubuntu@133.125.39.168:/tmp/
#    （VPS上で）
sudo mv /tmp/kasumin.conf /etc/nginx/sites-available/
sudo ln -sf /etc/nginx/sites-available/kasumin.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default

# 4) SSL証明書の取得はDNS切替後に行うため、まず443のserverブロックを
#    一時的にコメントアウトした状態で疎通確認
sudo nginx -t && sudo systemctl reload nginx

# 5) ファイアウォール（ufw。パケットフィルター不使用のためこれが唯一の防壁）
#    ※必ずこの順番で実行する。OpenSSH許可より先に enable するとSSHで締め出される
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable    # 確認プロンプトには y
sudo ufw status    # 22 / 80 / 443 がALLOWであることを確認

# 6) OSセキュリティ更新の自動化（推奨）
sudo apt install -y unattended-upgrades
```

## デプロイ用SSH鍵とGitHub Secrets

```bash
# VPS上でデプロイ専用鍵を作成
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N "" -C "github-actions-deploy"
cat ~/.ssh/deploy_key.pub >> ~/.ssh/authorized_keys
cat ~/.ssh/deploy_key   # ← この秘密鍵をGitHub Secretsへ
```

GitHubリポジトリ（yoppii12/kasumin-hp）→ Settings → Secrets and variables → Actions → New repository secret:

| Secret名 | 値 |
| --- | --- |
| `VPS_HOST` | `133.125.39.168` |
| `VPS_USER` | SSHユーザー名（例: `ubuntu`） |
| `VPS_SSH_KEY` | 上記 `deploy_key` の中身（秘密鍵全文） |

登録後、Actionsタブから「Deploy to Sakura VPS」を手動実行（workflow_dispatch）し、
`/var/www/kasumin/index.html` が同期されることを確認。
※deploy.ymlはmainブランチへのpushで動くため、それまでに開発ブランチをmainへマージしておく。

## 切替（DNS変更 → SSL取得）

1. **本登録が完了していることを確認**（お試し期間の帯域制限解除）
2. **動作確認**: `curl -H "Host: kasumin.biz" http://133.125.39.168/` でトップページHTMLが返ること
3. **さくらのゾーン編集**: kasumin.biz の Aレコードを `34.111.141.225`（STUDIO）→ **133.125.39.168** に変更
   （**MX・TXT・enmaruのCNAMEは触らない**。ロールバックは `34.111.141.225` に戻すだけ）
4. DNS伝播後、**SSL証明書を取得**:
   ```bash
   sudo certbot --nginx -d kasumin.biz \
     --non-interactive --agree-tos -m info@kasumin.biz --redirect
   ```
   ※kasumin.conf の443ブロックをコメントアウトしていた場合は、certbot実行前に戻して
   `sudo nginx -t` が通ることを確認
5. 自動更新の確認: `sudo certbot renew --dry-run`
